## The three root causes (all measured, all fixed or routed around)

### 1. EDGE-levered inputs were sent through the lane march (commit 2722ad1)

`compose.py:_compose_once` routed every input net as lane-march + drop.
An EDGE-levered boundary input has no lane — its pos is the
producer-facing stub on the west/east edge — so `lx` (derived from minx)
pointed back EAST into the lever bank, and the march ran along the bank's
own row (z = median LOAD row) through the other boundary levers. Measured:
alu1 band 2 died "no ground for C: (-50,12) -> (-42,12)" at every spread.
Fix: route stub -> load directly with the full candidate set. Effect:
alu1 band 3 NO GREEN RUNG -> 494 blocks. No-op for non-hier recipes (no
`edge` key): suite bit-identical 144/322/224/214/2925/5499.

### 2. Bankdrop overshoot shorts an existing booster (this session)

With band 2 self-contained, all bands placed green but the OP0 bank drop
(bank lever -> band stub) detoured east PAST the stub and came back west
along the stub row, paralleling the band's own lane run: bare dust across
an existing booster (front -> new dust -> stub -> lane -> back) is a
front-joins-back ring the gate correctly rejects. Measured twice:
ring at (550,1,2), 8 east of stub (542,2), tail ...(556,2)->(551,2)->
(551,1)->(542,1); then ring at (10,1,2), 8 east of stub (2,2), same shape.
Fix (`compose.py`, bank branch only): on bank-leg failure, retry once
with a west-approach waypoint (stub.x - 8), routing everything fresh via
`_legs` (no manual trunk re-stamp, which re-entered its own cells:
"path re-enters (541,1,-89)", measured). Retry-only: green builds succeed
first try, geometry byte-identical; only a leg that already failed LOUD
takes the new path.

### 3. Shared-inverter fanout latches via repeater side-lock (recipe)

With the stitch landing, 2/32 vectors failed (both OP1=1): Y=1, want 0.
Forensics (settled-state DIFF): m0/m1 stuck lit, both gated by qn1; qn1's
NOT torch correctly OFF, yet qn1 dust lit (302/341 cells). Root: qn1's
lane runs as TWO adjacent rows (z=62+63) with boosters on one row whose
sides see the other row's dust. Per `sim.py:rep_locked` (wiki, user-
measured in game): side-powered repeater holds last output. The shape is
a self-sustaining latch: diodes drive the rows, rows power the diodes'
sides. Any transient sets it permanently; blank power-on should stay
dark, but the hazard is real vanilla behavior, so the ROUTER must not
build it. Fix at the recipe level (zero engine risk): one NOT per load
(`qn1a`/`qn1b`), so the two nets can never share a corridor (different
nets are sealed apart by the checkers). Same-date A/B: shared qn1 ->
2 RED vectors; split qn1a/qn1b -> 32/32 green.
